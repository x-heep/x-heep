# X-HEEP on ZCU104: Troubleshooting & Deployment Guide

This guide covers the solutions for deploying X-HEEP applications to a Zynq FPGA over XVC (Xilinx Virtual Cable), including optimizing slow GDB connections, fixing ELF file errors generated by LLVM/Clang, and bypassing GDB entirely for faster loading.

---

## 1. Cleaning up LLVM/Clang ELF Files

When compiling applications with custom ISA extensions (like Quadrilatero/`xtheadmatrix`) using LLVM/Clang, the compiler injects custom tags into the `.riscv.attributes` section and heavy DWARF debug symbols. OpenOCD's internal ELF parser doesn't understand these, resulting in errors like `wrong ELF class: ELFCLASS32` or `failed buffering IHEX image`.

**The Solution:** Use GNU `strip` to remove the confusing debug information and explicitly delete the `.riscv.attributes` section while preserving the actual code and memory layout (including `.data_interleaved`).

Run this on your build server before loading:
```bash
riscv32-unknown-elf-strip -g -R .riscv.attributes sw/build/main.elf -o sw/build/main_clean.elf
```

---

## 2. Fast Loading via OpenOCD & Telnet (Recommended)

Loading standard ELF files via GDB over a network-based XVC JTAG connection is inherently slow. The fastest and most reliable way to load an application into the RISC-V RAM is to bypass GDB and send commands directly to OpenOCD via Telnet.

**Step 1:** Open a new terminal and connect to the OpenOCD server:
```bash
telnet localhost 4444
# (If telnet is missing, use: nc localhost 4444)
```

**Step 2:** Run the following sequence of commands to load and execute the clean ELF:
```tcl
# Stop the processor from running the BootROM loop
halt

# Load the stripped/cleaned ELF directly into RAM
load_image sw/build/main_clean.elf

# Write '1' to the SOC_CTRL_BOOT_EXIT_LOOP register to break the BootROM trap
mww 0x20000008 1

# Start execution at the application entry point
resume 0x00000180
```

## 3. Optimizing the Remote GDB Connection (Alternative)

If you *must* use GDB for step-by-step debugging, you will notice "keep_alive() not invoked" or "negative acknowledgment" warnings due to the slow XVC bridge. 

You can speed up the connection and stop the warnings by making GDB infinitely patient and disabling packet acknowledgments.

Use this initialization sequence in GDB:
```gdb
# 1. Increase timeouts to prevent dropouts over XVC
set remotetimeout 2000
set tcp auto-retry on

# 2. Disable Acknowledgments (Significantly speeds up the TCP stream!)
set remote noack-packet on

# 3. Optimize payload size for the XVC driver
set remote memory-write-packet-size 1024
set remote memory-write-packet-size fixed

# 4. Connect and load
target extended-remote localhost:3333
monitor halt
load sw/build/main_clean.elf
set {int}0x20000008 = 1
continue
```
